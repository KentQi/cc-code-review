# Changelog

## 1.18.4 — 2026-10-29

Clears the remaining P2/P3 backlog (the triage in `audit/TRIAGE.md`): the guard-policy holes, the runtime/protocol rough edges, prompt/playbook consistency, and the test/packaging debt. No behaviour change in the happy path; the changes below are the ones a caller can observe.

- **Guard policy (security-adjacent).** `git branch -u<ref>` (and `-u <ref>`, `--set-upstream`) is refused — it writes `.git/config` from a read-only review (P2-11). In fix mode the two guard files (`scripts/pre-tool-hook.js`, `src/shell-guard.js`) can no longer be written, so reviewing this package can't disarm every later run (SEC-15). Review mode now refuses to `Read` secret material inside the repo (`.env*`, `id_rsa*`, `*.pem/*.key`, `credentials`, `.ssh/.aws/.gnupg`, `.netrc`, `.pgpass`; `.env.example`-style templates stay readable) (SEC-23). A Bash payload whose `command` is not a string is denied instead of allowed (SEC-24), and `NotebookEdit` now reads `notebook_path` so fix mode can actually edit notebooks (SEC-25).
- **Loopback detection** normalises the forms `URL.hostname` actually produces: `[::1]`, `localhost.`, zone ids and IPv4-mapped IPv6 — the local-gateway Bearer token can no longer be routed through an HTTP proxy by spelling the host differently (SEC-09).
- **Transcript recovery works on macOS again**: `isAllowedTranscriptPath` compares realpaths (with the nearest existing ancestor for missing tails), so the `/var` vs `/private/var` spelling no longer makes a 429-killed subagent's recovered report silently vanish (R-7).
- **Process lifecycle**: SIGTERM/SIGINT/SIGHUP exit with 143/130/129 instead of 0, so a host can tell a signal from a clean shutdown (R-21); a client that closes stdin now triggers the same shutdown path as `transport.close()` (measured before: a running review kept billing after stdin closed); `transport.onclose` runs the SDK's own cleanup first (P-12).
- **Cache/TTL honesty**: npm-root probe failures expire after 60 s (was permanent), and `--version`/`--help` caches carry a 5-minute TTL, so an in-place upgrade is picked up without restarting the host (R-8/R-9).
- **Robustness**: `parseResultJson` parses pretty-printed results, `parseUnrecognizedModels` handles nested JSON, `looksLikeLaunchAck` no longer discards a real report that starts with the ack sentence, the 2-hour sweep flag is set only after a successful readdir, and the dead `agentResults` map (which pinned every tool_result in memory) is gone (R-11/R-14/R-15/R-16/R-19).
- **Async contract**: the first response is bounded by a 20 s soft preflight budget (probes that time out degrade with a warning instead of hanging the call), `resolveClaudeCliForCall` waits for the settled CLI probe, `cancel:true` without a jobId is an error, job retention is a 10-entry / 32 MiB budget (an evicted result polls as `isError` + `status:"evicted"`), and every job-shaped `structuredContent` carries `{jobId, status, repoPath}` (P-03/P-05/P-06/P-11/P-14/P-20).
- **Tool metadata**: the four tools carry `title` + `annotations` (`readOnlyHint` for env/status) and register through `registerTool` when the SDK provides it, with a fallback for older SDKs (P-13).
- **Validation tightened**: `focus` must be a single line (tabs/newlines/CR refused), `outputLanguage` is ≤20 chars with no sentence punctuation, and a PR reference whose owner/repo starts with `-` is refused (P2-7/P3-1/P3-3).
- **Prompt/playbook**: one report contract (already in 1.18.3) is now also the SKILL.md text; the fleet is described as "5 briefs + 3/5 split finders" (3+5=8, 5+5=10) instead of "verbatim"; `scope=auto` order is PR > branch > working-dir > last commit everywhere; CONFIRMED=85-100 / PLAUSIBLE=75-84 / REFUTED=0 is documented, so the `>= 75` filter and "keep CONFIRMED and PLAUSIBLE" select the same set; a stale skill that cannot be refreshed now degrades to the bundled fleet pipeline instead of running the old one silently (P2-2/P2-3/P2-8/P2-9/P2-10/P2-12/P2-13).
- **Packaging**: `files` is narrowed to the runtime set (tarball 30 files/789 KB → 15 files/551 KB) and a new `scripts/pack-test.mjs` (38 checks) asserts the tarball contents and boots the packed server; `scripts/lib/mcp-client.mjs` replaces the six hand-rolled stdio clients in the free suites; `init.mjs` writes its config atomically (temp + fsync + rename) and no longer half-writes on failure.
- Suites: shell-guard 260, audit-fixes 300, p0-regression 126, validation 23, pack 38, cross-cases 150/150, smoke PASS — `npm test` green (7 suites).
- **Upgrade note**: the policy tables changed, so a running MCP host now refuses to start a review until it is restarted (the stale-policy self-test). `focus`/`outputLanguage` inputs that used to pass may now be rejected.


## 1.18.3 — 2026-10-29

Third pass: the items the previous two rounds left open, plus two findings from the maintainer's re-review (the policy fingerprint was cached for 5 minutes, and a run killed by a signal after printing a result was still reported as success).

- **[P1-16] Two concurrent fix-mode reviews on the same repository could overwrite each other's working tree.** Fix mode now takes a per-repository lock (`activeFixRepos`, keyed by the resolved path) for the duration of the run; a second fix request is refused with an actionable message while read-only reviews stay unrestricted. The lock is released on every settle path *and* on every preflight refusal, so a rejected call cannot leave a repository locked.
- **[P1-8] A cancelled synchronous review lost the paid-for work.** `waitForResult=true` never registered a job, so when the client cancelled, the SDK dropped the response and the subagent reports were unreachable. Both review and followup now create and register the job *before* branching: a cancelled sync call leaves a pollable job (`claude_review_status` with no jobId lists it by repository), and the synchronous return value is unchanged.
- **[P2-14] The stale-process fingerprint check was cached for 5 minutes.** The guard self-test result carries a TTL, but the hook is spawned from disk on every call — so an upgrade without a host restart could run up to 5 minutes with two different policies while everything looked green. When `codeDrift()` says the sources on disk are newer than the process, the self-test now runs with `refresh: true` and refuses immediately.
- **[SEC-14] `CLAUDE_REVIEW_ALLOW_UNGUARDED=1` also bypassed a *failed* guard installation.** That is exactly the case it must never bypass: the run would advertise a guard while no command is policed. The escape hatch now applies only to a guard the operator deliberately switched off (`CLAUDE_REVIEW_SHELL_GUARD=0`); installation and self-test failures always refuse, with instructions to fix the guard.
- **[P2-7] A run killed by a signal (or exiting non-zero) after printing a result was reported as success.** Only the JSON event was consulted. The report is now preserved, but the result is `isError: true` with `status: "completed_with_error"`, a banner naming the signal/exit code, and `exitCode`/`signal` in structuredContent (followup too).
- **[P2-4] Result size had no bound.** A very large report could exceed what an MCP client will deliver. `claude_review_status` now caps the text and `structuredContent.report` at 512 KiB with UTF-8-safe truncation, a marker line, and pointers to the log/partial-report files; `job.result` itself is untouched, so repeated polls do not accumulate markers.
- **[P2-1] Two report formats coexisted in one prompt.** `REPORT_FORMAT`, the bundled `SKILL.md` block, the native appendix and the fallback prompt are now one contract, verbatim: `## Code Review Summary` / `<verdict>`, `## Findings (N)` with one `### [SEVERITY] title — path:line` block per finding + What/Why/Fix/Evidence, severity `critical | major | minor | nit`, `## Notes`, and an explicit no-findings branch. The fleet prompt carries the block exactly once.
- **[P2-5] `cancel-test.mjs` only worked on Windows** (`tasklist`). It now inspects `ps -axo pid=,command=` on POSIX and matches the resolved claude CLI path, so the real-CLI cancellation path can be exercised on macOS/Linux (still opt-in and billed).
- **[scanner] Three more command-executing git keys are refused**: `pager.<subcommand>`, `core.askPass`, `sequence.editor` (live values only — a dead path stays a note; `pager.*` booleans are inert and allowed). UNC values (`//server/share` or the backslash form) are refused *before* any filesystem probe, so a Windows UNC `core.attributesFile`/`[include]` no longer stalls the pre-spawn scan for ~21 s.
- Suites: shell-guard 238, audit-fixes 272, p0-regression 95, validation 16, cross-cases **149/149** (C1–C26: new C23 signal-exit, C24–C26 concurrency/sync-job), smoke PASS — `npm test` green.

## 1.18.2 — 2026-10-29

A second atomic audit (ten P0, ten P1) was run against 1.18.1 with every finding reproduced against real git / real hook processes before counting. Every P0 and every P1 is fixed below; the doc claims the audit falsified are now true in code, not just in prose.

- **[P0] Repository-controlled `core.sshCommand` could execute during a review.** The config scanner used `\bcommand\s*=`, which never matches `sshCommand` (camelCase: `h` is a word char), so `repoRunsGitPrograms()` returned no refusals while the allowlisted — and prompt-suggested — `git remote show origin` ran the repo's command twice before any network I/O. The scanner now reads config through `git config --file <cfg> --no-includes --list -z` (normalised keys, `GIT_HARDENING_ARGS` + isolated `gitSpawnOpts`) and refuses `core.sshCommand`, `core.fsmonitor`, `core.pager`, `core.gitProxy`, `credential.helper`, `core.attributesFile`, `diff.external`, and every live `diff.*`/`filter.*` driver; the regex path remains as a fallback when git is unavailable. The reviewer child process also gets `GIT_CONFIG_*` command-scope neutralisation (7 keys) so its own `git` calls cannot be steered by repo config.
- **[P0] `core.attributesFile` was never scanned.** Git has three attribute sources; only the worktree `.gitattributes` and `.git/info/attributes` were read, so a repo could point `core.attributesFile` at its own file and have `git log -p` execute a textconv (measured: 6 executions, scanner saw nothing). That file is now a third attribute source: in-repo regular files are scanned, out-of-repo/irregular/oversized targets are refused.
- **[P0] `MAX_ATTR_FILES` hit inside the directory loop did not set `truncated`** — the scan stopped silently instead of failing closed as its own comment and the 1.18.0 changelog promised. Now it refuses. (The audit's 4100-file repro was invalid — files named `aN.gitattributes` are not attribute files and were never counted; the honest fixture is one `.gitattributes` per directory, and the regression uses that.)
- **[P0] `echo` could exfiltrate host credentials.** `echo` was exempt from path checking and a bare `$VAR` was not modelled as substitution, so `echo $ANTHROPIC_API_KEY`, `echo ~/*`, `echo ../*` were all allowed by the real hook (the child process inherits the host environment, and `SECURITY.md` promises no credential exfiltration). `$VAR`/`$1`/`$?` are now substitution and unquoted globs/`~` in `echo` operands are refused — quote-protection is tracked by the tokenizer, so the legitimate literal forms (`echo 'price: $5'`, `echo '*'`) still run, while `echo $ANTHROPIC_API_KEY` and `echo ~/*` are denied. The tool description and SKILL.md say literal text only.
- **[P0] `tr` file operands were unchecked** (defense in depth: neither BSD nor GNU `tr` takes FILE operands, so the audit's "arbitrary read" overstated it — but the pipe sink is now path-checked like every other sink).
- **[P0] The hook's Read branch failed open.** When `realContainment()` threw (repo root deleted/renamed mid-run, unreadable parent, symlink loop) `rel` became `null` and the check was skipped, so `Read /etc/passwd` passed — while the Write branch denied. Read now denies on the same conditions, including `rel === null`.
- **[P0] A hook that could not read its stdin exited 0**, which the CLI reads as "no opinion" — the call ran unguarded. It now emits a deny decision and exits non-zero (`onFailure: "block"` is the second line of defence).
- **[P0] `baseRef` was validated by two different validators.** `HEAD~1`/`feature@2` passed `index.js` and were then silently dropped by `prompt.js`, so a fleet review reviewed a different diff with no sign of it. One exported validator is now the single source of truth; a ref the preflight accepts is the ref the prompt uses (range operators `..`/`...` are refused instead of half-honoured), and the error text no longer recommends a value that gets discarded.
- **[P0] `scope=pr` without `pr`** rendered "the GitHub pull request undefined" into the prompt and, on the native path, silently reviewed a different target. It is now refused before any paid work.
- **[P0] The followup path passed an empty denial set to `shellChainingNote()`**, so every command the guard had correctly blocked was reported as "RAN WITHOUT BEING BLOCKED — treat this repository as hostile". Followup now classifies `permission_denials` exactly like review, and reports its own allowlist gaps too.
- **[P1] The shipped SKILL.md confidence scale (0/25/50/75/100) contradicted its own `>= 80` filter** — only 100-point findings survived. Filter and tool description are now `>= 75`, matching the "real, important, will be hit" anchor.
- **[P1] Active JSONL journals were not actually protected**: `activeSubagentFiles` was written and never read, so the 20-file prune and the 2-hour sweep could delete a journal a live job still referenced. Both sweeps now skip active journals (and the run's own journal), and the set is cleared when the run settles.
- **[P1] `cross-cases`' C7 assertion was vacuous** (the array was passed in the `cond` slot), so "no allow rule is prefix-shadowed by a deny rule" could never fail. It now asserts the filtered length.
- **[P1] The P0 regression suite was marked `optional`** — deleting the only file that locks the P0 security fixes kept `npm test` green. It is required again; a missing suite is a failure.
- **[P1] The test suite leaked real credentials into `$TMPDIR`**: `cross-cases` spawned `init.mjs` with the full host environment and never removed its temp tree. It now scrubs `ANTHROPIC_*`, injects a sentinel token, proves the written config carries only that sentinel, and removes the tree on exit/crash/signal.
- **[P1] The log/guard directory trusted whatever was at `/tmp/cc-code-review`.** `mode: 0o700` only applies on creation, and on Linux `/tmp` is shared — a pre-created directory (or a symlink to an attacker's) received run logs and `guard-settings-*.json`, which claude reads at spawn time. Both paths now refuse symlinks and foreign ownership and force 0700.
- **[P1] `claude_review_env` could throw on a malformed `ANTHROPIC_BASE_URL`** (`new URL()` unguarded) instead of reporting it. Guarded and reported as unparseable.
- **[P1] `overrides` never reached consumers** (npm only honours the root project's overrides), so the `@hono/node-server` pin was inert for anyone installing the package. It is a direct dependency now.
- **[P1] Model substitution was blind to claude→claude downgrades**: `sameModelFamily()` returned true for any `claude-*` effective model, so a gateway silently running Sonnet as Haiku produced no `⚠ MODEL SUBSTITUTION`. Families (opus/sonnet/haiku) are compared when a model was requested.
- **[P1] `pipeline=native` + shadowed skill** returned through `err()` instead of `preflightFail()`, leaking the guard settings file and its in-flight mark on every such call.
- **Stale-process detection now has teeth.** The hook exposes a hash of the policy tables (`CC_REVIEW_GUARD_INFO=1`) and the pre-run self-test compares it with the server's in-memory policy; an upgrade without a host restart is refused instead of running two different policies — the "the guard self-test refuses to run" promise README/SECURITY made is finally true.
- **Audit corrections recorded** (so the next pass does not re-chase them): `tr` has no FILE operand in BSD/GNU coreutils (the guard change is defense in depth, not an arbitrary-read fix); the 4100-file `MAX_ATTR_FILES` repro was invalid; `echo /etc/passwd` prints a literal, not file contents — the real leak was wildcard/`$VAR` expansion.
- Suites: shell-guard 238, audit-fixes 272, p0-regression 95, validation 16, cross-cases 139/139 (C1–C22), smoke PASS — `npm test` green.

## 1.18.1 — 2026-10-29

A second five-expert audit (this time with every P0 re-executed against the real hook, real bash and a real stdio MCP client before it counted) found that 1.18.0's security claims did not all hold. Everything below was reproduced first, fixed second, and locked with a regression test third.

- **[P0] The shell guard judged the raw command string, not bash's argv.** `$'...'` (ANSI-C quoting) and backslash escapes (`\-exec`, `\--output=`) are expanded by bash before the command runs, so every token-exact deny table was blind to the flag hidden inside them; `-o<file>`-style glued short options (`sort -o/tmp/x`, `rg -f/etc/passwd`) were treated as self-contained flags. Measured before the fix: `find . -name x $'-exec' sh -c 'echo PWNED > /tmp/x'` was ALLOWED and executed; `git diff \--output=/tmp/x` wrote outside the repo. `parseCommand` now produces the argv view bash will execute, refuses ANSI-C/locale quoting outright, and `pathArgs`/`FLAG_KINDS` understand glued short options.
- **[P0] `.GIT` (and `.Git`) write bypass is now actually closed.** 1.18.0's changelog claimed this fix; the hook was still case-sensitive and the deny globs were lowercase-only, so `Write repo/.GIT/hooks/pre-commit` was allowed and landed in the real `.git/hooks/`. The hook now normalises case and separators, and the permission deny list carries every case spelling. Regression: `p0-regression` asserts all three spellings.
- **[P0] fix mode could plant persistence.** The deny list only named `.git` and secret files, so a prompt-injected reviewer could write `.claude/settings.json` (project hooks), `.envrc` (direnv), `.github/workflows/*` (CI), `.vscode/`, `.idea/`, `.mcp.json`, `.gitmodules`, `.gitattributes`/`.gitconfig` (diff drivers run programs) — each fires after the run, on the user's machine. Both layers (hook + permission globs) now refuse them, with a message that names the file and why.
- **[P0] Repository-supplied git drivers could execute code.** The `.gitattributes` scan only looked one directory deep, and a section header sharing its line with the first key (`[diff "evil"] textconv = cmd`, legal git config) registered no driver — so `git diff` executed repo-chosen commands. The scan is now recursive (depth 16 / 4000 files), understands same-line and dotted (`[diff.evil]`) headers, and **fails closed if it hits a bound** instead of scanning "most" of the tree. Regression: `p0-regression` covers all four shapes.
- **[P0] A committed symlink could freeze the whole server.** `repoAttributeFiles`/`repoConfigFiles` used `readFileSync` with no `lstat`, no size cap and followed links: `.gitattributes -> /dev/stdin` (recreated by `git clone`) blocked the single-threaded event loop forever, `/dev/zero` allocated without bound. Every repo-metadata read now goes through `readRepoFile()`: regular files only, realpath confined to the owning tree, 1 MiB cap surfaced as a refusal. Config-family reads follow links only where git itself does (verified against real git), so the fix does not open a new blind spot.
- **[P0] An empty report was returned as success.** `ok` never checked that the reviewer produced anything, so "no output" and "no findings" looked identical to the client (and a `.gitattributes`/hook failure could look like a clean review). Empty review **and** empty followup replies are now `isError:true` with `status: "empty_report"`, a banner that says the reviewer produced no report, and the log/partial-report paths; async jobs settle as `failed`.
- **[P1] Credentials no longer travel in results.** The env-vs-`settings.json` mismatch note printed both full tokens; `claude_review_env`, the failure banner and the gateway-changed warning printed full `ANTHROPIC_BASE_URL` (userinfo/query included); `scripts/init.mjs` echoed the token to stdout and wrote `~/.zcode/cli/config.json` world-readable. Values are masked to a prefix + length (URLs to origin only), and the config is written `0600` in a `0700` directory.
- **[P1] Absolute in-repo reads under a symlinked prefix were refused.** `isInsideRepo` realpathed the root but not the token, so on macOS (`/tmp`, `/var` are symlinks) `find "<repo>" -name x` was denied — burning review turns and contradicting README's "both sides are realpathed". Both sides are now resolved; the failing regression test passes unchanged.
- **[P1] `baseRef` could inject flags into the native `/code-review` command.** `"main --fix"` passed validation (no shell metacharacters, no leading `-`) and claude parses its own flags anywhere in the string — so a `fix=false` run could request `--fix`/`--comment`. `baseRef` is now a single git-safe ref token: no whitespace, git ref charset only.
- **[P1] `postToPR` was a dead feature.** The prompt instructed `gh pr comment` and the permission layer granted it, but the hook's policy had no `gh pr comment` prefix — the command was always blocked. The rule now exists for the hook (which only subtracts) and is still granted to the model **only** when `postToPR=true`.
- **[P1] A completed run could be reported as timed out.** Only `close` was observed, so a finished claude whose descendant still held the stdio pipes was marked `timedOut` at the deadline: the paid-for report was discarded and the descendants survived. `exit` is now observed, the process group is reaped immediately, and the run settles with its real exit code (measured: 21.5 s + `timedOut` → 136 ms + `ok`).
- **Test gate.** `npm test` used `&&`, so the first red suite swallowed the other 272 checks; it now runs every suite through `scripts/run-tests.mjs` and fails if any did. Added `scripts/p0-regression-test.mjs` (68 checks, real hook process, free/offline) and added it to the existing CI workflow. (The audit worked from a working copy that was missing dotfiles, so its "the repository has no CI" finding was an artifact — `.github/workflows/ci.yml` existed; it simply did not run the new suite.) Two Windows-only test cases are now platform-aware and `validation-test` no longer hard-codes `C:/` paths.
- Suites: shell-guard 235, audit-fixes 272, p0-regression 68, validation 16, cross-cases 136/136, smoke PASS — `npm test` green on macOS, for the first time since 1.18.0.

## 1.18.0 — 2026-10-29

Every finding from the five-expert atomic audit of 1.17.0 was verified against the code (the security ones executed twice — the guard and the live hook process — before counting as confirmed), then fixed. Nothing was trusted on the auditor's word alone.

- **[P0/H1] Backslash-newline line continuation no longer hides flags.** `parseCommand` kept `<backslash><LF>` as word content while bash deletes the pair, so `find . \<LF>-delete` (and up to `-exec sh -c id`, `git diff \--no-index /etc/passwd`, `--output=` writes, `rg \--pre`) ran with the flag live while every deny check saw a mangled word. Fixed by joining continuation lines the way bash does; regression-locked byte-exactly at the tokenizer level. (A continuation after a space glues the next word into the FIRST command's arguments — `git status <paths>` — which is read-only and stays allowed, matching bash semantics.)
- **[P0/H2] `sed` is no longer a permitted pipe sink.** Its script language writes (`w`/`W`), executes (`e`) and reads (`r`) files in forms the old parser provably missed — `sed 's/.*/cmd/e'` executed a command on this machine from repo-controlled input. `head`/`tail` cover the line-range need; the rest goes through Read.
- **[P0/H3] Brace expansion cannot smuggle paths.** `{..,/etc}`, `{~/x,y}` passed the lexical repo check as one token; tokens containing `{`/`}` are refused.
- **[P0/M] Smaller policy holes**: `git branch --unset-upstream` (writes `.git/config`), the case-sensitive `.GIT` write bypass in fix mode, `sort --compress-program` (executes a repo-supplied program) and `sort -T` (temp files outside the repo) are all refused.
- **[P1/N1] Fix mode rides the native command's `--fix` flag.** The audit found the native command DOES support `--fix` (usage line `[levels] [--fix] [--comment] [<target>]`), so the old premise "fix has no native equivalent" was wrong; `pipeline=native` + fix at low..xhigh now appends `--fix` and the appendix instructs applying fixes instead of contradicting itself with a read-only line (the old dead code would have guaranteed FIX MODE VERIFICATION FAILED).
- **[P1/N2] The PR URL can no longer inject command arguments.** `https://github.com/o/r/pull/9/ low --fix` passed validation and its tail became additional `/code-review` arguments (claude parses its own flags anywhere in the string). The URL form now must end at the number; `owner/repo#123` and bare numbers unchanged.
- **[P1/N3] scope=auto with a pr forwards it** as the native target — the old code silently dropped it for scope=auto although the tool advertises "auto: PR if pr given". Plus: an empty-but-dirty or commit-less repo is treated as "no parent commit" (the native `HEAD~1` target could never exist there).
- **[P1/N4] Empty notifications recover from the ack's transcript.** An agent that notified with an empty summary and no `outputFile` of its own skipped both recovery paths although the launch ack held a valid transcript; the notification branch now falls back to the ack path and the finish pass retries recovery for any recorded-but-empty report, appending a correction line to the JSONL journal.
- **[P1/N5] The followup tool keeps its subagent reports.** It grants Agent/Task, so cancellations/timeouts/failures used to drop reports the JSONL already held; all interruption and failure paths now carry the reports and the journal path like the review tool.
- **[P1/N6] The JSONL journal survives retention.** The 20-file prune and the 2h sweep could delete a `subagents-*.jsonl` a live job still referenced mid-synthesis; active journals are now protected.
- **[P2 consistency]** The two pipeline texts the model sees no longer contradict each other: the SKILL.md briefs emit the native candidate shape (`file`/`line`/`summary`/`failure_scenario`), its branch-range step avoids the denied `git merge-base`, and the prompt's "chains are hard-denied" line is replaced with the real segment rule (chains of permitted reads run). The fleet line carries the level's own angle mix (3+5 at medium/high, 5+5 at max) instead of the max taxonomy on every level; `effort=xhigh` now maps to reviewLevel max (claude shares one playbook factory for both). `installSkillIfMissing` is a real parameter again (its false default actually degrades to the fleet pipeline; `CLAUDE_REVIEW_AUTO_INSTALL_SKILL=1` sets the default), the retired diff-scaled formula is gone from the tool describes, the stale "diff-sized fleet"/"5 reviewer subagents" copy is gone from the blurbs, the EN architecture diagram and SECURITY.md describe the current model, and the EN "git paths are checked" claim is corrected (git pathspecs are not path-checked — the escape hatches are refused outright).
- Suites: shell-guard 233 (+15: continuation joins, braces, branch writes, sort hatches, sed removal), audit-fixes 272, validate 16, cross-cases 136/136 (C21 gains: native argv-in-argv assertion, fix rides `--fix`, scope=auto forwards pr, root-commit reroute with its explanatory note).

## 1.17.0 — 2026-10-29

The fleet now mirrors claude's own review playbook, read out of the binary instead of guessed. No hard-coded "15".

- **What the native code actually says** (claude.exe 2.1.311, `ro("max")` / `no()` / `to()`):
  - low: `1 diff pass → no verify → ≤4 findings`, no subagents.
  - medium/high: `3+5 angles × 6 candidates → 1-vote verify` — **8 finder subagents**.
  - max/xhigh: `5+5 angles × 8 candidates → 1-vote verify → sweep` — **10 finder subagents**, then **one verifier per deduped candidate** (CONFIRMED / PLAUSIBLE / REFUTED, keep the first two), then **one sweep finder** for gaps; findings capped at 15.
  - If the Agent tool is missing, the playbook says to do every angle and every verification inline instead of erroring — which is why the "do NOT spawn subagents" text appears in the fallback template, not the main path.
  - The separate "spawn about `clamp(2..8, lines/150)` finders" string is a hint injected only for the claude-sonnet-5 family at high+; it is not a universal rule.
- **The MCP now follows that structure.** The previous prompt invented level floors (5 at max) plus a diff-scaled formula, which is not what claude does; it produced 10 finders + 3 verifiers on a 672-line diff. The new prompt states phase 1 (all finders in ONE message, background agents), phase 2 (one verifier per surviving candidate, batched in one message), phase 3 (sweep), and the 15-finding cap. The bundled skill says the same thing, so the two cannot disagree.
- **Measured on the same 672-line fixture, effort=max:**

## 1.15.0 — 2026-10-28

The last open read channel: the reviewer's Bash readers could reach anywhere on disk. They are now scoped to the reviewed repository.

- **Path scoping for every read the guard allows.** `find`/`rg` path arguments, the file arguments of every pipe sink (cat/head/tail/wc/uniq/cut/tr/grep/sort/sed), and git's own path flags are checked against the repo root. Refused: absolute paths outside, `..`, `~` (the shell expands it), `$VAR` (cannot be resolved statically), and in-repo symlinks or junctions that point elsewhere — the check realpaths the deepest existing ancestor, exactly like the Edit/Write boundary, so a lexical-only check cannot be walked out of.
- **Reads that were never path arguments are refused outright**: `git diff --no-index` and `git blame --contents` (arbitrary path reads), `sed -f` (a script file can contain `w`/`W`/`e`), `wc`/`sort --files0-from` (a list of paths that may point outside), and `uniq`'s second positional (an output file — a write, not a read).
- **The hook now fails closed for Bash when it is not given the repo root**, the same rule the write/read tools already followed. `runClaude` always sets it; a broken setup is refused instead of silently running unscoped.
- **`echo` joined the allowed surface.** It reads nothing and writes nothing, and `git show HEAD && echo "=====" && git log` is the one separator a reviewer reaches for — a real run burned a turn on exactly that. `git show HEAD && echo x; rm -rf /` is still refused (rm is not in the policy).
- **The guard self-test probes a construct, not a program.** It used `git status; echo PWNED`, which the new policy legitimately allows; it now uses command substitution (`git status $(curl …)`), which is refused structurally no matter what the program list says — a self-test that can be satisfied by policy drift is not a self-test.
- **Verified end-to-end on the real CLI.** In one probe the allowlisted `rg -n hello .` ran with no denial while `rg -n TOP-SECRET "<a directory outside the repo>"` was denied, and `cd "<repo>" && git show --stat HEAD` still runs. The paid smoke completed with `denials=0` and 2/2 reviewer reports captured.
- Suites: shell-guard 203 (+36: path scoping in and out, `~`/`$VAR`/`..`, sinks reading outside, the outright-denied forms, echo, the hook's fail-closed root), audit-fixes 243, validate 16, cross-cases 118/118 (C6 also proves an in-repo `rg` passes, an outside `rg`/`find`/sink read is refused, and Bash without a root fails closed).

## 1.14.0 — 2026-10-28

The shell guard stops conflating "compound command" with "unsafe command". Every Bash call is now judged segment by segment, so the shapes models actually write run while the ones that matter stay blocked.

- **Root cause, not a workaround.** The guard rejected every `&&`/`|`/`;`. Models constantly write `cd "<repo>" && git show HEAD`, so each of those became a denied call that burned a turn — without reducing risk, because the same two commands run one-per-call were allowed anyway. Real runs showed it: 4 guard blocks + 2 permission denials per review (`denials=2 guardBlocked=4 bashCalls=10`).
- **What it decides now.** Each segment must be a permitted read-only command (git status/diff/show/log/blame/rev-parse/ls-files, the exact branch/remote/stash reads, find, rg, the gh reads) or a pipe sink (head/tail/cat/wc/uniq/cut/tr/grep/sort/sed -n). `cd` is allowed only as the first segment and only when it realpaths to the reviewed repository root, where every Bash call already starts. Redirection, `$()`/backticks/`${}`, background `&`, `find -delete/-exec/-fprint…`, `rg --pre`, `git --output=`, `sed -i`, a `w`/`W`/`e` sed script and `sort -o` are still refused, now on the segment that carries them.
- **One policy, not two.** `shell-guard.js` exports `BASH_POLICY`; `prompt.js` renders the `Bash(...)` rules from it and the hook judges against the same table. The rendered list is byte-identical to the previous hand-written one except for the new `Bash(cd:*)`.
- **Why `Bash(cd:*)` is safe, established from the binary.** claude 2.1.311's hook-output sanitizer passes `permissionDecision: "deny" | "ask"` and drops `"allow"` (`permissionDecision==="deny"||==="ask"?…:void 0`), and `updatedInput` does not land on that path. A PreToolUse hook therefore cannot grant — it can only subtract. So the allowlist must be the thing that lets the *shape* through the engine's gate, and the hook decides where the `cd` lands. A hook-allow + engine-deny pair wastes a turn; it can never weaken enforcement.
- **Verified end-to-end on the real CLI.** A dedicated probe ran `cd "<tmp repo>" && git show --stat HEAD` under `--permission-mode manual` with the real allowlist and the installed hook: the command ran, `permission_denials` was empty. The paid smoke on the same fixture went from `denials=2 guardBlocked=4 bashCalls=10` ($0.47) to `denials=0 guardBlocked=0 bashCalls=3` ($0.40), with both reviewer reports captured and the JSONL on disk.
- **The skill now carries the contract to the subagents.** A subagent never sees the skill file, so the parent is told to paste an explicit execution contract into every subagent prompt (cwd is the repo root, no `cd`, the allowed program list, no redirection/substitution). That removes the remaining reason for a reviewer to guess.
- **Reporting matches the new semantics.** Denials are bucketed as unlisted-program / unsafe-form / substitution, and the note names the offending segment and what was allowed instead of saying "shell-chained".
- Suites: shell-guard 159 (rewritten for the segment contract: allowed chains, allowed pipes, `cd` inside and outside the root, every write/execute form, the real 17-command replay), audit-fixes 242, validate 16, cross-cases 113/113 (C6 now also proves a permitted chain and a `cd`-to-root chain are allowed).

## 1.10.0 — 2026-10-28

"Why can't this MCP reproduce the complete output of the same prompt in Claude Code?" — root-caused by reverse-engineering the installed claude CLI (2.1.311, a Bun single-file executable; bundle carved out of the binary and read directly, with the REA MCP driving the target inspection) and diffing six real run logs in `%TEMP%/cc-code-review/`. Two independent causes, both fixed here:

- **The reviewer subagents' reports never reached the caller.** claude 2.1+ forwards subagent activity to the parent stream-json (the `Agent` dispatch tool_use, the subagent's own messages tagged with `agent_id`, and the `tool_result` carrying its final report) — the old parser assumed the opposite ("subagent calls never reach the parent's stream", true of pre-2.1 CLIs) and threw it away. The MCP returned only the parent's synthesis, so the caller saw one summary where Claude Code shows five experts working. The result now carries every dispatched subagent's report: a `## Reviewer subagent reports` section in the text (each capped at 4000 chars, full stream in the log file) and `subagents[]` in structuredContent.
- **The run silently swapped models.** `~/.claude/settings.json`'s env block — written by CC Switch when switching providers — pins `CLAUDE_CODE_SUBAGENT_MODEL=MiniMax-M3.1-Flash` and remaps every `ANTHROPIC_DEFAULT_*_MODEL_NAME` to the same; `--setting-sources user` loads exactly that file. The CLI's own resolution chain (tool > agent frontmatter > env > inherit, verified in the binary) therefore runs all five "expert reviewers" on the substituted model, and claude logs `[claude-code:unrecognized_model] {"model":"MiniMax-M3.1-Flash","query_source":"agent:builtin:general-purpose"}` on stderr for every one. Observed across the run logs: main sessions on step-5-preview / MiniMax-M3 / MiniMax-M3.1-Flash depending on the gateway's current provider. The result now reports **model provenance** (requested vs effective, main + subagents, `modelProvenance` in structuredContent, `effective_model` in the metadata) and a prominent `⚠ MODEL SUBSTITUTION` warning when they differ — the same reports are not comparable to a direct Claude Code session, and the caller is told instead of left to diff two different models' outputs. The same rewrites, plus a process-env `ANTHROPIC_BASE_URL` silently overridden by the settings file (claude applies the settings env over the process env), are also warned about before the run starts.

Also in this round:

- Verified-false on the way: `--permission-mode manual` is NOT being skipped (the init event reports `permissionMode: "default"` because the CLI maps `manual` → `default` — they are the same mode, an alias, not a downgrade); `Task`/`Agent` dispatch IS permitted under the manual allowlist in headless runs (the Oct 19 log's inline-only review was the substituted model's behaviour, not a permission denial); subagent text/thinking does reach the stream without `--forward-subagent-text` on 2.1.311.

C10's dead-gateway case now isolates `CLAUDE_CONFIG_DIR` (the real settings.json env was overriding the test's `ANTHROPIC_BASE_URL` — the same precedence this release warns about, caught by the suite itself).
